# T04 — CI workflow + `MANIFEST.sha256` (the real wall)

**Where:** the `slopnet` repo. **Model:** medium. **Depends on:** T02, T03.
**Read first:** `build/SLOPNET_DESIGN.md` §2 (the four layers) and §3.

## Why this task matters most

Local hooks are bypassable (`--no-verify`); CI re-running the **identical**
check scripts is the wall, and the manifest makes tampering with the
machinery loud. All four design reviewers called this the make-or-break.

## Deliverables

1. **`.github/workflows/slopnet.yml`** — on `push` and `pull_request`,
   three jobs:
   - **law:** checkout, then run every `checks/*.sh --all`; any failure
     fails the job. Must use the *same files* the local hooks use — no
     reimplementation, no drift.
   - **manifest:** `sha256sum -c MANIFEST.sha256` (macOS/Linux portable:
     use `shasum -a 256 -c` fallback if needed). Failure message must say,
     in one line, that machinery changed without a manifest update and
     that this is either tampering or a maintenance change that must
     regenerate the manifest in the same commit.
   - **register-audit:** fail if no `register/<HEAD-commit-author-date>.md`
     is tracked (same rule as `checks/register.sh --all`; calling that
     script directly is preferred).
2. **`update-manifest.sh`** — regenerates `MANIFEST.sha256` covering
   exactly: `checks/*.sh`, `hooks/*`, `lefthook.yml`, `.gitleaks.toml`,
   `install.sh`, `doctor.sh`, `update-manifest.sh` itself, and
   `.github/workflows/slopnet.yml`. Deterministic order (sorted paths).
   Header comment: "Run me whenever machinery legitimately changes;
   commit the result in the same commit."
3. **`MANIFEST.sha256`** — generated by running the script now.

## Rules

- The workflow must run on a plain `ubuntu-latest` with no third-party
  actions except `actions/checkout`. No secrets required, no network
  beyond checkout (fallback-mode checks must pass without binaries —
  T02 guarantees `secrets.sh` regex fallback).
- No new names. Log in `LOG.md`.

## Acceptance (operator runs these)

```bash
./update-manifest.sh && shasum -a 256 -c MANIFEST.sha256 && echo manifest-ok
```
```bash
printf '\n# tamper' >> checks/junk.sh && (shasum -a 256 -c MANIFEST.sha256; git checkout -- checks/junk.sh)
```
(the middle command must FAIL — that failure is the guard working)
- After pushing: the Actions tab shows all three jobs green on the
  template repo itself.
