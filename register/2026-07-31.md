Reverted 07:15. It made things worse and the operator was right to say so.

Putting the panel fill behind the frame does not make the colour meet the red edge. A box-drawing character is a thin line in the middle of its cell: give `─` a grey background and the cell is grey with a red hairline through the middle, so grey shows above and below it. Do the same to `│` and grey shows either side. The result is a solid colour block with the red frame floating *inside* it, which is what the screenshot showed.

demo_agency draws frames on the field for exactly this reason — `rule()` uses `bg(VOID)`. The original was right and my reading of it was wrong.

What the operator has actually been describing, repeatedly, is that the black frame cell sits between the fill and the red line, so the colour stops one cell short. That is real. It is a consequence of using a thin glyph as the border at all, and it has more than one possible answer — a solid red block character as the edge, no side borders with the fill running to the margin, or the demo's own arrangement kept as-is. Those look different from each other and I have now guessed wrong three times in a row.

So: reverted to the 07:15 state, and asked rather than guessed a fourth time.

## 09:30 — claude (Fable) did

The operator sent a screenshot of `scripts/show_panels.py` — 34 provider panels that look right — and asked why the code that already works could not simply be used. Reading it settled two things I had got wrong out loud.

`edge = bg(VOID) + fg(FRAME)`. StormCode draws the border cell on black with a red hairline, exactly as this app already did. The black cell is not a defect; it is the design. I had spent hours treating it as one, and told the operator the requirement was geometrically impossible. It was not impossible — it was already met.

`logo()` returns the badge plus `CELLS - 1` trailing spaces, because a terminal paints a wide bitmap but only advances the cursor one cell. AppKit advances the full glyph width by itself. Measured rather than assumed: a line of badge + ten X ends at the same pixel as a line of two letters + ten X, so the badge advances two cells here and the fill paints across both. Porting that correction verbatim would have broken the layout — the same design needs opposite handling in the two environments.

The real difference was density. Their panels carry a right-aligned state word and several dim rows, so the brand fill dominates and the frame is incidental. Ours were two thin rows, so the frame dominated. The tiles now carry READY or SET UP right-aligned on the header row, which is what makes the eye land on the name and then on where it stands.
